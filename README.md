# Ruffus el Hornero — Bot de WhatsApp + Instagram

Bot conversacional **menu-based** para las cuentas de WhatsApp Business e Instagram de Horno.
Responde como _Ruffus el Hornero_, el pajarito del equipo que mueve la correspondencia 🐦‍🔥:
da la bienvenida, muestra servicios/equipo/proyectos desde Supabase y deriva las consultas
guardándolas como _leads_.

## Stack

- **WhatsApp:** [`@whiskeysockets/baileys`](https://github.com/WhiskeySockets/Baileys) v6.7.0 (protocolo WhatsApp Web, no oficial).
- **Instagram:** Meta Instagram API con Instagram Login (oficial, webhook HTTP).
- **Datos:** Supabase REST sobre el schema `horno` (lectura con anon key + RLS pública).
- **Persistencia de leads:** tabla `horno.leads` con columna `source` (`whatsapp` | `instagram`).
- **Runtime:** Node ≥18, TypeScript, ejecutado con `tsx`.

## Supabase setup

El bot usa el proyecto Supabase `obvnhcccovvruvpooyap` ("stage") y el schema `horno`.

### 1. Exponer el schema `horno`
_Project Settings → API → Exposed schemas_ → agregar `horno`.

### 2. Grants de lectura/escritura
Ejecutar en el SQL Editor:

```sql
grant usage on schema horno to anon;
grant select on all tables in schema horno to anon;
```

### 3. Migración de leads

Ejecutar `migrations/001_unify_leads.sql` en el SQL Editor. Esto:
- Crea la tabla `horno.leads` con columna `source`
- Migra los datos existentes de `horno.whatsapp_leads`
- Crea una vista `horno.whatsapp_leads_v` para backward-compat

### 4. Tabla de leads

```sql
create table if not exists horno.leads (
  id          bigint generated by default as identity primary key,
  source      text not null check (source in ('whatsapp', 'instagram')),
  contact     text not null,
  name        text,
  option      text not null,
  message     text,
  status      text not null default 'nuevo',
  metadata    jsonb not null default '{}'::jsonb,
  created_at  timestamptz not null default now()
);

alter table horno.leads enable row level security;
create policy "anon can insert leads" on horno.leads for insert to anon with check (true);
```

### WhatsApp (index-whatsapp.ts)

Al iniciar imprime un **QR** en la terminal. Escanealo con el WhatsApp Business.
La sesión se guarda en `.bot-auth/` (gitignored).

### Instagram (index-instagram.ts)

El bot corre un servidor HTTP en el puerto 3000 (configurable con `PORT`).
Necesitás un endpoint **público HTTPS** para que Meta pueda mandarle webhooks.
En desarrollo podés usar ngrok o similar:

```bash
ngrok http 3000
# La URL de ngrok se configura en Meta App Dashboard como webhook callback
```

## Menú

El bot responde con un menú de 4 opciones:

1. **💡 Tengo una idea** → pide la idea y guarda lead
2. **📅 Eventos** → Próximamente (aún sin datos)
3. **🤔 ¿Qué onda Horno?** → submenú:
   - Proyectos activos
   - Servicios
   - Conocer al equipo
4. **💬 Quiero hablar con alguien** → pide consulta y guarda lead

Comandos: `menu`, `0` → vuelve al inicio. Cada opción acepta el número o la palabra.

## Leads

`saveLead()` inserta en `horno.leads` (source, contact, name, option, message, status).
Cuando entra un lead, el bot envía un WhatsApp de aviso a los números en `BOT_NOTIFY_NUMBERS`.

## Deployment

### Railway (recomendado)

Crear **dos proyectos** en Railway desde el mismo repo Git:

**Servicio 1 — WhatsApp:**
- Root Directory: `/`
- Build Command: vacío
- Start Command: `BOT_ENTRYPOINT=whatsapp npx tsx src/index-whatsapp.ts`
- Volumen montado en `/app/.bot-auth`

**Servicio 2 — Instagram:**
- Root Directory: `/`
- Build Command: vacío
- Start Command: `BOT_ENTRYPOINT=instagram npx tsx src/index-instagram.ts`
- Puerto: `3000`
- Volumen montado en `/app/.bot-auth-ig`

Ambas necesitan las mismas variables de Supabase.

### Dockerfile

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json package-lock.json* ./
COPY tsconfig.json ./
COPY src ./src/
COPY migrations ./migrations/
RUN npm install --omit=dev && npm install -g tsx
ENV NODE_ENV=production
ENV BOT_ENTRYPOINT=whatsapp
CMD ["npx", "tsx", "src/index-${BOT_ENTRYPOINT}.ts"]
```

## Setup de Meta App (Instagram)

1. Crear app en [developers.facebook.com/apps](https://developers.facebook.com/apps) tipo Business
2. Agregar producto Instagram > "API setup with Instagram login"
3. Vincular cuenta de Instagram Business de Horno
4. Generar access token (60 días) y Account ID
5. Configurar webhook en la app:
   - Callback URL: `https://tu-dominio.up.railway.app/api/webhooks/instagram/horno`
   - Verify Token: el que definiste en `BOT_HORNO_IG_VERIFY_TOKEN`
   - Suscribirse a: `messages`, `messaging_postbacks`, `messaging_reactions`, `messaging_seen`
6. Suscribirse a la cuenta por API:
   ```bash
   curl -X POST \
     "https://graph.instagram.com/v26.0/me/subscribed_apps?subscribed_fields=messages,message_reactions,messaging_postbacks,messaging_seen&access_token=TU_TOKEN"
   ```

## Notas

- **Baileys es no oficial** (WhatsApp). Riesgo de baneo a alto volumen.
- **Instagram API es oficial** (Meta). Sin riesgo de baneo por usar la API.
- **Ventana de 24h** en Instagram: el bot puede responder dentro de las 24h posteriores al último mensaje del usuario.
- El token de Instagram caduca a los 60 días. Hay que implementar un job que lo refresque.
