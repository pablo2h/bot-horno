# Ruffus el Hornero — Bot de WhatsApp

Bot conversacional **menu-based** para el número de WhatsApp Business de Horno.
Responde como _Ruffus el Hornero_, el pajarito del equipo que mueve la correspondencia 🐦‍🔥:
da la bienvenida, muestra servicios/equipo/proyectos desde Supabase y deriva las
consultas del equipo guardándolas como _leads_.

## Stack

- **Transporte:** [`@whiskeysockets/baileys`](https://github.com/WhiskeySockets/Baileys) v6.7.0 (protocolo WhatsApp Web, no oficial).
- **Datos:** Supabase REST sobre el schema `horno` (lectura con anon key + RLS pública).
- **Persistencia de leads:** tabla `horno.whatsapp_leads` (escritura con anon + política RLS de insert).
- **Runtime:** Node ≥18, TypeScript, ejecutado con `tsx`.

## Supabase setup

El bot usa el proyecto Supabase `obvnhcccovvruvpooyap` ("stage") y el schema `horno`.

### 1. Exponer el schema `horno`
_Project Settings → API → Exposed schemas_ → agregar `horno`.

### 2. Grants de lectura/escritura
Ejecutar en el SQL Editor:

```sql
grant usage on schema horno to anon;
grant select on all tables in schema horno to anon;
```

### 3. Tabla de leads
Ejecutar en el SQL Editor:

```sql
create table if not exists horno.whatsapp_leads (
  id          bigint generated by default as identity primary key,
  phone       text not null,
  name        text,
  option      text not null,
  message     text,
  status      text not null default 'nuevo',
  created_at  timestamptz not null default now()
);

alter table horno.whatsapp_leads enable row level security;

create policy "anon can insert" on horno.whatsapp_leads
  for insert to anon with check (true);
```

### 4. Datos de prueba (opcional)
La tabla `horno.whatsapp_leads` necesita existir. Los datos de servicios/proyectos/equipo
deben existir en el schema `horno` del proyecto.

## Instalación local

```bash
pnpm install
cp .env.example .env
# editar .env con las credenciales de Supabase
pnpm dev
```

Al iniciar imprime un **QR** en la terminal. Escanealo con el WhatsApp Business
(menú > Dispositivos vinculados). La sesión se guarda en `.bot-auth/` (gitignored).

## Variables de entorno

```env
BOT_SUPABASE_URL=https://obvnhcccovvruvpooyap.supabase.co
BOT_SUPABASE_ANON_KEY=your_anon_key_here
BOT_NOTIFY_NUMBERS=549XXXXXXXXX
```

| Variable | Requerido | Descripción |
|---|---|---|
| `BOT_SUPABASE_URL` | Sí | URL del proyecto Supabase |
| `BOT_SUPABASE_ANON_KEY` | Sí | Publishable key del proyecto |
| `BOT_NOTIFY_NUMBERS` | No | Números del equipo a notificar (ej: `5491112345678,5491112345679`) |

## Menú

El bot responde con un menú de 4 opciones:

1. **💡 Tengo una idea** → pide la idea y guarda lead
2. **📅 Eventos** → Próximamente (aún sin datos)
3. **🤔 ¿Qué onda Horno?** → submenú:
   - Proyectos activos
   - Servicios
   - Conocer al equipo
4. **💬 Quiero hablar con alguien** → pide consulta y guarda lead

Comandos: `menu`, `0` → vuelve al inicio. Cada opción acepta el número o la palabra.

## Leads

`saveLead()` inserta en `horno.whatsapp_leads` (phone, name, option, message, status).
Usa la **anon key** (la tabla tiene política RLS de insert para anon).

Cuando entra un lead, el bot envía un WhatsApp de aviso a los números en `BOT_NOTIFY_NUMBERS`.

## Notas

- **Baileys es no oficial.** Riesgo de baneo a alto volumen. Para producción conviene
  migrar a BSP oficial (360Dialog/Twilio): la lógica de `menu.ts` no cambia, solo `index.ts`.
- **LID JIDs:** cuando el bot recibe mensajes de Linked Devices (JID termina en `@lid`),
  no puede usar listas interactivas (`listMessage`) — WhatsApp no routea respuestas desde LID.
  El bot detecta JIDs LID y envía menús como texto plano con opciones numeradas.
- **Volumen de sesión:** montá un volumen en `.bot-auth/` para que la sesión persista
  entre reinicios. Si no, el bot pide re-escanear el QR en cada arranque.
